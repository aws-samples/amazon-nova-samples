# ドキュメント OCR / 抽出向け Amazon Nova Lite のファインチューニング

このリポジトリでは、特化した OCR タスク向けに Amazon Nova Lite モデルをファインチューニングする方法を示します。特に、スキャンされた W2 税務フォームから構造化データを抽出することに焦点を当てています。マルチモーダル学習データの準備、カスタムモデルのファインチューニング、税務文書抽出タスクでの性能評価を学べます。

## 内容

- [01_data_preparation.ipynb](./01_data_preparation.ipynb) - OCR 機能付き Amazon Nova Lite のファインチューニング用データを準備します。このノートブックでは、W2 税務フォーム画像データセットの処理、S3 へのアップロード、適切な形式のプロンプト作成、Bedrock conversation schema に従った train / validation / test データセットの準備を扱います。

- [02_finetune_on_bedrock.ipynb](./02_finetune_on_bedrock.ipynb) - Amazon Bedrock 上で Amazon Nova Lite マルチモーダルモデルをファインチューニングします。このノートブックでは、適切なハイパーパラメータによるファインチューニングジョブ作成、進行状況の監視、学習メトリクスの可視化、ファインチューニング済みモデルのデプロイ作成、サンプル画像での推論テストを扱います。

- [03_evaluate_custom_models.ipynb](./03_evaluate_custom_models.ipynb) - ベースモデルとファインチューニング済みモデルを評価・比較します。このノートブックでは、さまざまなフィールドカテゴリ（従業員情報、雇用者情報、収入など）にわたる抽出精度を測定し、エラーパターンを分析し、ファインチューニングによる改善量を定量化する包括的なベンチマークフレームワークを提供します。

## 前提条件

- Amazon Nova Lite モデル向け Amazon Bedrock にアクセス可能な AWS アカウント
- Bedrock、S3、および IAM ロール作成に対する適切な IAM 権限
- 必要ライブラリ（boto3、pandas、matplotlib など）を備えた動作可能な SageMaker または Python 環境

## ユースケース

税務文書からの情報自動抽出は、特に数値の正確性が重要であるため、固有の難しさがあります。このプロジェクトでは、W2 税務フォームのようなドメイン特化文書に対して、ファインチューニングが OCR モデル精度を大幅に改善できることを示します。

ファインチューニング済みモデルは、ベースモデルの 55.87% に対して 85.31% の総合フィールド抽出精度を達成しており、29.44% の大きな改善となっています。

## 重要事項

- Custom Nova model のオンデマンド推論デプロイは現在 us-east-1 AWS リージョンで利用可能です
- マルチモーダルモデルのファインチューニングジョブ完了には数時間かかる場合があります
- 合成 W2 税務フォームデータセットには 2,000 枚の画像が含まれます
- 不要なコストを避けるため、評価後は AWS リソースをクリーンアップしてください

## データソース

このプロジェクトでは、CC0 ライセンスの合成 W2 税務フォーム データセット [Fake W-2 (US Tax Form) Dataset
](https://www.kaggle.com/datasets/mcvishnu1/fake-w2-us-tax-form-dataset/data) を使用しています。
